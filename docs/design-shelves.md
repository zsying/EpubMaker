# 设计稿：多书架（切换 / 密码 / 迁移 / 批量迁移）

状态：**已实施**（2026-11-01，三条待拍板项按推荐值 A1 / B1 / C1 落地；实现记录见 ADR-40）
日期：2026-11-01
关联：ADR-5（生词本是跨书资产）、ADR-11（列表只传缩略图）、ADR-16（手机只有元数据编辑）、ADR-30（分享进来的书排队等页面来取）

---

## 1. 需求拆成四个动作

| # | 动作 | 落到哪里 |
|---|---|---|
| 1 | 创建不同的书架 | 新的 `shelves` 表 + `books.shelf_id` |
| 2 | 方便地切换当前书架 | 书架页头部「书架名 ▾」→ 弹层 |
| 3 | 为书架设置密码 | `shelves.pw_hash`（PBKDF2）+ 进程内解锁表 |
| 4 | 迁移书籍（含批量） | 书架页多选 → 底栏「移动到…」 |

第 4 条里的"批量"需要**多选**，而当前书架页没有多选——这是本设计里唯一一处真正的**新交互**，其余都是既有模式的延伸。

## 2. 现状（对照代码，不是推测）

- `books` 没有归属字段（`db.go` 的 `schema`：id/title/…/tags/file_hash），全库一本书架。
- 书籍文件在 `<books>/<bookID>/content`（`storage.BookDir`），**路径与书架无关**。所以"迁移"只是改一行 `shelf_id`，不搬文件、不动 zip、不影响阅读进度/书签/批注（它们都挂在 `book_id` 上）。这决定了迁移是**零风险操作**，可以放心批量。
- `ListBooks(keyword)` 一条 SQL 出全表，前端 `shelfCache`（模块级、仅内存）缓存上一次结果。
- 手机端头部在 360px 已经排了 h1 + 「N 本」+ 搜索/排序/＋ 三个图标（AGENTS.md 记过"真机 360 是压力位，flex 先压 h1"）。
- 全应用**没有任何密码/锁定代码**（`grep 密码|password|PIN` 只命中日志与 wifi 分享的内部锁）。
- Go 1.26，标准库 `crypto/pbkdf2` 可用（已实测编译运行），**不新增依赖**。

## 3. 数据模型

```sql
CREATE TABLE IF NOT EXISTS shelves (
  id         TEXT PRIMARY KEY,
  name       TEXT NOT NULL DEFAULT '',
  position   INTEGER NOT NULL DEFAULT 0,
  pw_hash    TEXT NOT NULL DEFAULT '',   -- '' = 无密码；否则 pbkdf2-sha256$<iter>$<salt>$<hash>
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL
);

-- 追加在 books 的最后（file_hash 之后），保持 fresh 与 migrated 库的 SELECT * 列序一致
ALTER TABLE books ADD COLUMN shelf_id TEXT NOT NULL DEFAULT '';
CREATE INDEX IF NOT EXISTS idx_books_shelf ON books(shelf_id);
```

迁移（沿用 `migrate()` 的"每条 `_ = d.Exec`，幂等"风格）：

1. 建表（在 `schema` 常量里，fresh 库一次到位）
2. `INSERT OR IGNORE INTO shelves (id,name,position,...) VALUES ('default','书架',0,...)`
3. `UPDATE books SET shelf_id='default' WHERE shelf_id=''`

老库升级后：一本书不少，全部落在唯一那个叫「书架」的书架上，页面长相与今天**完全一致**。

**为什么不复用 `tags`**：标签是多对多的、可叠加的、纯字符串；书架是一对多的容器，而且**密码必须挂在容器上**——不能挂在一个字符串上。两件事必须分开，`tags` 继续做筛选。

**一本书只属于一个书架**（单选）。跨书架的"组"用标签表达，二者正交。

## 4. 锁的边界（这一节最重要，请重点看）

**它是一块窗帘，不是一个保险柜。** 我不打算把它说成"加密"，因为数据库是一个明文 SQLite 文件，任何拿到文件的人都能读。密码保护的是"**手机被人顺手拿走时的界面**"，不保护磁盘。

据此，拦截范围是有明确边界的：

### 拦

| 面 | 行为 |
|---|---|
| 书架列表 | 锁定书架的书不进 `ListBooks` 结果 |
| 书架页 | 当前书架若锁定，不画网格，画解锁屏 |
| 阅读器 | `GetBook` / `RenderChapter` 对锁定书架的书直接拒绝（否则书签页的残留链接、历史 URL 能绕过） |
| 书签页 / 批注页 | `ListAllBookmarks` / `ListAllAnnotations` 过滤掉锁定书架的书（它们会带书名） |
| 回收站 | `ListTrash` 同上，免得"删掉"成了查看书名的后门 |
| 写入 | 锁定书架不可改名、不可迁入、不可设置/清除密码、不可删除——一律要求先解锁 |

### 不拦（**明确说明**，不是遗漏）

| 面 | 为什么 |
|---|---|
| 生词本里的原句 | 生词本按 ADR-5 是"跨书资产"，一个词被收进本子就不再属于那本书。要按书架过滤会把它的定义撕开 |
| 已有的 AI 对话 | 对话是记录，正文里可能引用过书名与原句。锁不追溯已经发生过的内容 |
| 书架名与书的**数量** | 弹层里显示「日记 · 3 本」但看不到是哪三本。名字可见是有意的：否则列表里凭空少一条，用户会以为数据坏了 |
| 正在读的那本书 | 自动上锁**不打断**正在进行的阅读。读到一半被踢出去是最差的手感 |

**锁状态存在进程内存里**（`library` 包内 `map[string]bool` + mutex），不落库：重启应用 = 全部重新上锁。这也是"必须由后端知道锁状态"的原因——前端过滤是装饰，后端过滤才是边界。

**自动上锁**：应用切到后台超过 **5 分钟**（`visibilitychange` 记时），回到前台时对所有已解锁书架调 `LockShelf`。不打断正在读的那本书（见上表）。

**失败退避**：连续错 5 次 → 10 秒，之后每次翻倍，上限 15 分钟；成功即清零。计数在内存里（重启清零，接受这个洞——它挡的是"拿在手里试"，不是离线爆破；离线爆破本来就挡不住，因为文件是明文）。

### 忘记密码

见第 9 节「待你拍板」的第 2 条。默认方案：**应用内没有任何自助恢复**。设密码时明写「忘记后无法在应用内找回」；`shelves` 表里那行 `pw_hash` 是唯一逃生口，写进 AGENTS.md 供技术支持使用（`UPDATE shelves SET pw_hash='' WHERE id='…'`）。

## 5. 接口

Go（`app/internal/library/shelf.go`，由 `backend.go` 绑定）：

```go
ListShelves() ([]ShelfDTO, error)
CreateShelf(name string) (*ShelfDTO, error)
RenameShelf(id, name string) (*ShelfDTO, error)
DeleteShelf(id string) (moved int, err error)          // 书移回默认书架，绝不删书
SetShelfLock(id, oldPassword, newPassword string) (*ShelfDTO, error)  // "" = 清除
UnlockShelf(id, password string) (UnlockResult, error)  // {ok, retryAfterMs}
LockShelf(id string) error
MoveBooks(bookIDs []string, shelfID string) (int, error)
```

签名变更（前后端同版本发布，没有兼容负担）：

```go
ListBooks(keyword, shelfID string)                  // shelfID="" = 全部未锁定书架（仅空态「在其他书架搜」用）
ImportPaths(paths []string, shelfID string)         // 空 = 默认书架（系统分享/Wi-Fi 分享走这条）
WebdavImport(conn, items, shelfID)
```

`ShelfDTO` = `{id, name, position, bookCount, hasLock, locked}`。

**导入落哪里**：书架页的 ＋、WebDAV 页、在线书库页都传"当前书架"（前端从 `localStorage['epubmaker.shelf']` 读）。系统分享与 Wi-Fi 分享那一刻没有"当前书架"这个概念（ADR-30），落**默认书架**——这是刻意选择：后台进来的书进锁定的书架时没人能输密码。

## 6. 交互设计

### 6.1 切换器：头部药丸 + 弹层（两端同一个）

h1「书架」变成当前书架名，后面一个小 ▾；「N 本」并入药丸变「12 本」的次要文字，把栏位让给长书名（360px 下药丸 `max-width` 截断，`title` 给全名）。

```
手机 360px                         桌面
┌──────────────────────────────┐   ┌────────────────────────────────────┐
│ 苏联史 ▾ 12 本      🔍 ⇅ ＋  │   │ 苏联史 ▾ 12 本          搜索  导入 │
└──────────────────────────────┘   └────────────────────────────────────┘
   历史  传记  小说                 （标签 chips 原样不动）
┌──────┐┌──────┐┌──────┐           
│      ││      ││      │
```

点药丸 → 弹层（sheet）：

```
┌─────────────────────────────┐
│ 书架                        │
│ ✓ 苏联史              12 本 │  ← 当前，✓ 在左
│   小说                34 本 │
│ 🔒 日记                3 本 │  ← 有密码且本次未解锁
│ ＋ 新建书架                 │
│ 取消                        │
└─────────────────────────────┘
```

- 点一行 = 切换（并记住，下次打开应用还在这个书架）。
- 行尾一个 `⋯`：重命名 / 设置密码 / 取消密码 / 删除书架。（桌面也能点，不依赖长按。）
- 锁着的那行点下去，弹层**原地**变成密码输入（标题变「解锁 日记」），不叠第二层浮层。
- 不摆「全部书架」这个伪书架：锁定书架要么出现在里面（泄内容）、要么不出现（那就不是"全部"）。搜索因此在书架内进行；书架内搜不到时，空态给一个「在其他书架搜」，点了才用 `shelfID=""` 跨书架搜，卡片上标出所属书架。

### 6.2 多选与批量迁移

**进入**：手机走长按 —— 长按一本书弹出的菜单里第一项变「多选（可批量移动）」，进去时这本已选中；桌面卡片本来就有 `.book-actions`，头部加一个「选择」按钮。手机上不给头部再加图标：360px 的四个图标位已经挤满。

**选中态**：

```
┌──────────────────────────────┐
│ 已选 3 本     全选   取消    │  ← 头部替换成选择条
└──────────────────────────────┘
  ┌──────┐ ┌──────┐ ┌──────┐
  │      │ │  ✓   │ │  ✓   │      ← 卡片左上角勾选圆点；tap 切换、长按不再弹菜单
  └──────┘ └──────┘ └──────┘
┌──────────────────────────────┐
│  移动到…      删除            │  ← 底栏（手机上压在 tab bar 之上，FAB 隐藏）
└──────────────────────────────┘
```

**移动到…** 弹层：列出除当前书架外的全部书架，锁定行带 🔒，点锁定行原地变密码输入，解锁后继续迁。迁完 toast「已移动 3 本到「小说」」，选择模式退出，书架重新拉取。

批量删除顺手做实（多选一开，逐个长按删除就没人能忍）：它走既有的软删除进回收站，可恢复。

### 6.3 书架管理（弹层里的 `⋯`）

| 动作 | 规则 |
|---|---|
| 新建书架 | 名字 1–24 字，首尾空格裁掉，重名拒绝（否则两个同名书架无法区分）；默认书架不能删，可改名 |
| 重命名 | 同上校验 |
| 设置密码 | 4–32 字符，任意字符（手机键盘默认数字键，但允许字母）；已有时需先输旧密码 |
| 取消密码 | 需当前密码 |
| 删除书架 | 二次确认写明「里面的 12 本书会移到「书架」，不会被删除」；锁定的要先解锁 |

## 7. 关键裁决（每条都带理由与否决）

1. **书架页不新增"书架 chips 行"。** 切换器塞进头部药丸：360px 上再加一行 chip（44px）会把网格推下去，而且它和标签 chips 抢同一种视觉语言；更要紧的是"切换可能要输密码"，那件事天然属于弹层，不属于一行 chip。
2. **锁状态在 Go 侧，不在前端。** 前端过滤只是化妆：`/books/:id/read` 一条 URL 就能绕过。所以 `GetBook`/`RenderChapter`/三个跨书列表都在 SQL 层过滤。
3. **迁移只改一行 `shelf_id`。** 文件按 `<bookID>` 存，与书架无关——所以迁移不动磁盘、不动进度、不动书签，可以一次几百本。反过来若按书架分目录存放，迁移就成了"搬文件 + 断所有相对路径"，那才是灾难。
4. **进锁定的书架必须解锁，锁定的书架也不能被写入。** 只挡读不挡写会出现"书被移进一个看不见的书架"，用户会认为是丢书。
5. **默认书架是普通书架，不是"全部"。** 它可改名、可设密码，只是不能删。
6. **弹层里锁的行显示数量。** 名字都看得见了，藏一个数字换不来安全，只换来困惑。
7. **切书架要清缓存。** `shelfCache` 是模块级内存缓存，现在只有一个数组；改成 `{shelfId, books, dict}`，`shelfId` 不匹配就当作没有缓存——否则切到新书架会先闪一下上一个书架的书（那是**泄密**，不只是闪一下）。

**否决**：①用 `tags` 表达书架（不能挂密码、不能表达唯一归属）；②按书架分目录存文件（迁移变搬文件）；③密码存明文或 SHA256 单轮（PBKDF2 120k 是标准库就有的东西，没有理由降级）；④"忘记密码"一键清除（等于锁没装，见待拍板第 2 条）；⑤手机头部再塞一个"选择"图标（360px 已经满，实测记忆在案）；⑥做书架拖拽排序（本版不需要，`position` 先按创建顺序）。

## 9. 待你拍板的三点（已按推荐值落地）

**A. 切换器形态**
- A1（推荐）：头部药丸 + 弹层。一套机制、能放数量与锁、密码提示有地方放。
- A2：头部下面加一行书架 chips，一点即切。少一次点击，但 360px 多一行 44px，且与标签 chips 视觉打架。

**B. 忘记密码**
- B1（推荐）：**应用内没有任何恢复**。锁才真的锁得住；忘记的人要找"删库里的 `pw_hash`"这条技术路径（会写进文档）。代价：万一忘了，书在磁盘上但应用里打不开。
- B2：允许"忘记密码 → 清除密码"（书架与书都保留）。方便，但任何人拿到手机都能一键把锁摘掉，等于没锁。

**C. 多选入口**
- C1（推荐）：手机从长按菜单进（不占头部），桌面用头部「选择」按钮。
- C2：两端都在头部加「选择」图标。统一，但手机 360px 会挤掉搜索或排序的位子。

确认（或改这三点）后我就开工，顺序按：数据层 → 接口 → 书架页切换/管理 → 多选与迁移 → 全量验证 → ADR-40 + AGENTS + CHANGELOG。版本号按你的规矩要升（`app/build/config.yml` 单一来源 + 5 处同步），等你发话再动。
